# Editorial Guide

**ID:** CONTENT-EDITORIAL-001 · **Status:** Proposed working guide · **Version:** 0.1.0

## 1. Purpose

Menjaga kualitas, konsistensi, dan ketercarian konten Mahira. Panduan ini merupakan baseline editorial yang harus disesuaikan dengan kebijakan organisasi, bidang riset, standar sitasi, dan hak publikasi yang berlaku.

## 2. Content principles

- Accuracy: claims, names, numbers, dates, and affiliations must be verifiable.
- Clarity: readers should understand the question, contribution, and relevance from title and summary.
- Attribution: authors, editors, contributors, data sources, and funders are credited according to policy.
- Transparency: methodology, limitations, conflicts, and corrections are disclosed where relevant.
- Accessibility: PDFs and web content should be readable, structured, and usable with assistive technology where feasible.
- Bilingual integrity: translation must preserve meaning, not merely literal wording.
- Rights: publication and third-party assets must have documented permission/license.

## 3. Publication type and metadata

The final list of types is a stakeholder decision. Potential examples in the project discussion include research report, policy brief, working paper, commentary, and other types; do not create taxonomy values until the organization approves them.

Proposed minimum publication metadata:
- title (per locale);
- slug (per locale if applicable);
- subtitle/deck (optional);
- summary/abstract (length rule per type TBD);
- publication type;
- desk and topic relation(s);
- author/contributor relation(s) and display order;
- publication date and optional updated date;
- language/locale and translation relation;
- publication status;
- access level and per-asset access override if approved;
- cover/thumbnail and downloadable assets;
- keywords/tags if approved;
- citation/reference metadata when applicable;
- methodology, acknowledgements, funder, disclaimer, rights/license where applicable;
- SEO title/description/social image, with sensible defaults.

## 4. Title and summary guidance

- Titles should be specific, informative, and faithful to the research.
- Avoid unsupported superlatives and claims.
- Summary should explain the issue, approach, key finding/contribution, and relevance without disclosing restricted full content if policy requires otherwise.
- Do not auto-generate an abstract and present it as author-approved.
- Set maximum lengths after examining real content and UX; the limit must allow both ID and EN.

## 5. Author and contributor metadata

Define the organization’s rules for name order, honorifics, affiliation, ORCID (optional), biography length, headshot consent, author ordering, corporate authors, translators, editors, and contributors. A publication must not display an inferred author based only on the CMS account that created it.

## 6. Citations and references

Select style(s) by publication type or organizational policy. Preserve external URLs/DOIs and source metadata. Do not invent citation details. Decide whether references are structured records, rich text, or both. External links should be checked and clearly distinguish source references from organizational endorsements.

## 7. Date and version policy

Distinguish publication date, last updated date, event date, and ingestion date. Use a consistent timezone convention for timestamps. When a publication is materially updated, show the update date and optional correction/change note. Preserve version history as required by editorial policy.

## 8. Translation policy

- Assign a language owner or reviewer for each locale.
- Record source locale and translation relationship.
- Mark translations stale when source changes materially.
- Preserve translated title/summary metadata and locale-specific slug.
- Do not publish machine translation without the organization’s review policy.
- Keep translated author names and official institution names consistent; do not translate proper names without a rule.

## 9. File and image guidance

- Use a descriptive asset title and meaningful original filename metadata.
- Record file format, size, language, version, and access class.
- Verify PDF text is selectable where possible and pages are correctly oriented.
- Ensure image rights and attribution are recorded.
- Cover art must represent the actual publication and must not mislead.
- Do not use stock/AI imagery as if it were a real event, person, field site, or research evidence.
- Private file classification must be explicit; never infer from filename or directory.

## 10. Editorial review checklist

- [ ] Title, summary, and metadata reviewed.
- [ ] Research claims and numbers have source/context.
- [ ] Author and contributor attribution verified.
- [ ] Type, desk, topic, and tags follow taxonomy.
- [ ] Publication date and update date accurate.
- [ ] References and disclaimers included where required.
- [ ] Rights/license and third-party assets approved.
- [ ] ID/EN quality and translation status reviewed.
- [ ] File opens and matches displayed metadata.
- [ ] Asset-level access classification confirmed.
- [ ] SEO and social metadata complete.
- [ ] Preview checked on mobile and desktop.

## 11. Governance items for stakeholder approval

- Official publication types and required metadata per type.
- Summary/abstract length and style.
- Citation standards.
- Author identity and profile policy.
- Review and correction policy.
- Rights/license and disclaimer templates.
- Translation ownership and quality assurance.
- Public access versus registered/subscriber policy.
