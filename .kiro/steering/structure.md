# Mahira — Repository Structure and Code Boundaries

## Current repository structure (2026-11-13)

```text
app/(site)/          # homepage `/` (Indonesian), its root layout and global styles
app/[locale]/        # locale root layout for /id and /en; /{locale}/publications index skeleton
app/(payload)/       # Payload admin (/admin) and REST (/api); mostly Payload-generated files
app/robots.ts        # robots; icon.svg and favicon.ico sit next to it
components/          # brand, home, site (header, footer, language switcher), ui
lib/                 # cms read layer, homepage view model, i18n, publication helpers, static homepage copy
payload/             # Payload config, collections, access, fields, hooks, db helpers, migrations, env gate, generated types
proxy.ts             # request gate: 404s while the CMS is off; admin login pre-check while it is on
tests/               # node:test suites: unit/, integration/, build/, helpers/
scripts/             # test runners and secret-scan
public/              # static assets, including logo variants
docs/                # CORE, decisions, architecture, specifications, engineering, design, content, legal, spikes, references
.github/workflows/   # CI (ci.yml)
.kiro/               # steering and skills
AGENTS.md            # Next.js-generated agent instruction block
```

The codebase is in M3 (MVP publication platform); `docs/MILESTONES.md` holds the current status. Not built yet: publication detail pages, search, SEO metadata, About, Learning Hub, public accounts. Do not treat planned folders as existing implementation.

## Current files to preserve and understand

- `app/(site)/page.tsx` is the homepage. It reads publications and topics from the CMS through the public read layer; with the CMS off it shows static copy and an empty-state note (DECISIONS §2.7).
- `app/(site)/layout.tsx` and `app/(site)/globals.css` own the homepage root layout and the current design tokens/styles (single token source is DEC-024, still open).
- `lib/cms/public-content.ts` is the only public read path for CMS data: published and public records only, no fallback locale, `overrideAccess: false`. Do not bypass it from pages or components.
- `lib/landing-content.ts` holds only static homepage copy (navigation, principles); it is not CMS-backed data.
- `app/(payload)/` files are generated by Payload. `admin/[[...segments]]/page.tsx` is hand-edited (`await connection()`, DECISIONS §2.10); keep that edit when regenerating or upgrading.
- `components/brand/mahira.tsx` contains the Mahira mark; `components/site/` provides the site shell; `components/home/` the homepage blocks.
- `public/logo/` contains multiple logo variants; choose variants according to the brand guide when accepted.

## Boundaries

- `app/` — route composition, layouts, loading/error states, route handlers.
- `components/` — presentation components grouped by domain and shared UI; no direct privileged database or storage access.
- `lib/` — server-side integrations, read layers, domain services, validation, access evaluator.
- `payload/` — CMS schema, access control, hooks, migrations.
- `docs/` — product, architecture, specification, engineering, content, and legal documents.
- `.kiro/` — Kiro workspace steering and skills.

Align new folder names with `docs/engineering/PROJECT-STRUCTURE.md`. Do not create speculative abstractions for future subscription/payment features.

## Naming and dependency boundaries

- Use descriptive kebab-case for route segments and filenames where it matches existing conventions.
- Use PascalCase for React component names and TypeScript types.
- Keep external provider SDKs behind server-side service/adaptor modules.
- Avoid circular imports and broad barrel exports that hide dependency direction.
- Put tests in `tests/` (`unit/`, `integration/`, `build/`, `helpers/`; DECISIONS §2.5).

## Root AGENTS.md is managed by Next.js

The current root `AGENTS.md` contains a generated Next.js rule block. Preserve the generated block. Put Mahira-specific persistent rules in `.kiro/steering/` rather than replacing or deleting the Next.js block.
